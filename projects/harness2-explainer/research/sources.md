# Source ledger: Harness² (harness2): Recursive Agent Harnessing for an Open World (Google Cloud AI Research + Northwestern University)

Researched: 2026-10-20

- **what-harness** (definition, event n/a): A harness is the system around a model that lets it act as an agent: prompts, tools, memory, skills, orchestration. 'Harnessing' is optimizing that system. README: "A harness is the system around a model that enables it to act as an agent: prompts, tools, memory, skills, orchestration, and more."
  - Google Research GitHub org, "google-research/harness2 README", published 2026-10-08: https://github.com/google-research/harness2
  - arXiv, "Harness^2: Recursive Agent Harnessing for an Open World", published 2026-10-09: https://arxiv.org/abs/2610.14224
- **frozen-weights** (core-claim, event n/a): Improves agents while keeping model weights fixed. README: "It connects two levels of recursion while keeping model weights fixed". Paper: harnessing = "optimizing the runtime scaffolding around a frozen base model"; "Model weights, stage instructions, and the decision rule remain fixed, while the library evolves."
  - Google Research GitHub org, "google-research/harness2 README", published 2026-10-08: https://github.com/google-research/harness2
  - arXiv, "Harness^2 (HTML v1), Sections 1 and 2.3", published 2026-10-09: https://arxiv.org/html/2610.14224v1
- **eight-components** (fact, event n/a): Eight editable harness components, each mounted as a file: system prompt, guardrails, memory, tool guidance, subagents, skills, scripts, and plugins (middleware plugin). Extends AHE's file-level decomposition by one component.
  - Google Research GitHub org, "README: Harness components", published 2026-10-08: https://github.com/google-research/harness2
  - arXiv, "Harness^2 Section 2.1", published 2026-10-09: https://arxiv.org/html/2610.14224v1
- **loop-task-level** (mechanism, event n/a): Task-level recursion: a contrastive Propose–Probe–Compose step. Run the current harness once as a reference; PROPOSE two candidate edits (an 'invariant' candidate for general agent weaknesses like planning, tool use, context, delegation; a 'domain-specific' candidate for the task's domain knowledge/procedures); PROBE: run each candidate on the same task under matched conditions and compare behaviour with the reference (a 'behavioral contrast'); COMPOSE: merge supported changes, revise conflicts, adopt one, or keep the current harness, then run the composed harness. No ground-truth answers are used. README: "propose edits, probe their effects on the same task, and compose a refined harness from behavioral contrasts between executions, without ground-truth feedback."
  - Google Research GitHub org, "google-research/harness2 README", published 2026-10-08: https://github.com/google-research/harness2
  - arXiv, "Harness^2 Section 2.2.1", published 2026-10-09: https://arxiv.org/html/2610.14224v1
- **loop-scaling** (mechanism, event n/a): Budget k scales the step. Parallel: probe k invariant + k domain candidates, produce k compositions, then an agentic selector picks the best anonymized deliverable. Sequential: chain k Propose–Probe–Compose steps. At k=1 both reduce to one step. README: "Parallel recursion explores wider; sequential recursion refines deeper."
  - Google Research GitHub org, "README: Experiments", published 2026-10-08: https://github.com/google-research/harness2
  - arXiv, "Harness^2 Section 2.2.2", published 2026-10-09: https://arxiv.org/html/2610.14224v1
- **loop-harnessing-level** (mechanism, event n/a): Harnessing-level recursion: after each task an experience reflector reviews the whole improvement record and saves the adopted harness plus evidence-supported lessons into a 'harness improvement library' (each entry = executable harness + EXPERIENCE.md). The next task starts from the same base harness, but proposals can reuse/adapt library entries. Paper: "Lessons are retained only when supported by execution contrasts".
  - arXiv, "Harness^2 Section 2.3", published 2026-10-09: https://arxiv.org/html/2610.14224v1
  - Google Research GitHub org, "README pipeline figure alt text", published 2026-10-08: https://github.com/google-research/harness2
- **headline-results** (result, event n/a): A single step (k=1) improves GLM-5 and Gemini 3.5 Flash over their base harnesses in all four model–harness configs (OpenCode, Codex). Max gains: +11.5 points WorkBuddy-Bench (GLM-5/OpenCode, 64.2 -> 75.7 avg), +4.5 points JobBench (Gemini 3.5 Flash/OpenCode, 31.5 -> 36.0), +11.8 percentage points LAB Partial pass rate (GLM-5/OpenCode, 59.6 -> 71.4). Means over three runs.
  - arXiv, "Harness^2 Abstract, Tables 1-2, Section 3.2", published 2026-10-09: https://arxiv.org/html/2610.14224v1
  - Google Research GitHub org, "google-research/harness2 README", published 2026-10-08: https://github.com/google-research/harness2
- **recursion-results** (result, event n/a): Parallel recursion at k=5 adds a further 2.9-3.9 points on WorkBuddy-Bench, 3.0-4.2 on JobBench, 2.6-6.7 pp on LAB Partial over a single step. Gemini 3.5 Flash/OpenCode WorkBuddy avg: base 72.4 -> k=1 77.5 (+5.1) -> k=5 80.8 (+8.4 total). JobBench same config: +4.5 at k=1 to +7.5 at k=5.
  - arXiv, "Harness^2 Sections 3.2 and 4", published 2026-10-09: https://arxiv.org/html/2610.14224v1
  - Harness² authors (GitHub Pages), "Harness² project page", published 2026-10 (undated page): https://harness2.github.io
- **weaker-beats-stronger** (result, event n/a): With one step, GLM-5 reaches 75.7 (OpenCode) and 75.3 (Codex) on WorkBuddy-Bench, above base Gemini 3.5 Flash's 72.4 and 74.5. Paper: "A weaker model with an improved harness can thus outperform a stronger one with its original harness."
  - arXiv, "Harness^2 Section 3.2", published 2026-10-09: https://arxiv.org/html/2610.14224v1
- **setup-models** (fact, event n/a): Frozen executors: Gemini 3.5 Flash and GLM-5 under OpenCode and Codex harnesses. Default harness editor: Claude Opus 4.8 under OpenCode. Library starts empty per benchmark stream. Same-model-as-editor test (k=2): all five models improve; GLM-5 +13.7 on LAB, Claude Opus 5 +3.3/+5.5/+3.0.
  - arXiv, "Harness^2 Sections 3.1 and 4", published 2026-10-09: https://arxiv.org/html/2610.14224v1
- **case-study** (result, event n/a): JobBench case study (Gemini 3.5 Flash, OpenCode): one task's score rose from 43.1 to 77.8 after an invariant guardrail (inventory inputs, trace figures, re-open and verify output files) and a domain skill for reconciling schedule/venue/labor/budget files.

- **caveats** (caveat, event n/a): Authors' limitations: extra executions and editor sessions add inference cost as budget grows (parallelism cuts latency, not compute); feedback is behavioural contrast plus model judgment, sensitive to run-to-run variability and shared model biases, and does "not guarantee correctness or establish that an adopted change will transfer to a different task." README: model-backed runs incur API costs; executor network is unrestricted and Codex runs with sandbox disabled; public benchmark rubrics may be online, so restrict network before evaluating. Results are benchmark evaluations (3 runs each), not production deployments. Recursion does not uniformly close gaps between harnesses; on LAB Partial, Meta-Harness leads for Gemini 3.5 Flash/Codex.
